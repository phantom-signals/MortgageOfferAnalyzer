## Context

`MortgageOfferAnalyzer.html:15` ships `<link rel="icon" id="favicon">` with no `href`. Line 610 fills it:

```js
$("favicon").href = "data:image/svg+xml," + encodeURIComponent($("mark").outerHTML);
```

Intent was one artwork definition: the `#mark` SVG in the `<h1>`. Cost is that the served markup declares no icon URL. Google's favicon crawler is a separate fetcher from Googlebot's renderer; it reads the HTML head and follows a URL. Empty `href` gives it nothing, and a `data:` URI gives it nothing it will index either — Google indexes an icon it can crawl at a URL.

Assets present: `icon-180.png` (180x180, generated by `tools/mkicon.py`), referenced by `rel="apple-touch-icon"`, by `math.html` as its `rel="icon"`, and by two `_redirects` rows.

## Goals / Non-Goals

**Goals:**
- Served HTML declares a crawlable icon URL with no script run.
- Live tabs keep the theme-aware SVG icon.
- Saved offline copy still shows an icon.
- One raster in the repository, one artwork definition.

**Non-Goals:**
- `.ico` format or a `/favicon.ico` route.
- Multi-size icon set, web app manifest, PWA install.
- Making the icon theme-aware without script.
- Proving Google reindexes; that is on Google's schedule.

## Decisions

**Static `href` on the existing link, script overwrites it.** One attribute added, no new element. Alternatives: a second `<link rel="icon">` alongside the script-filled one — browsers pick among multiple icon links unpredictably, and the script would still need to know which one to touch; dropping the script overwrite entirely — loses the light/dark SVG icon in tabs, which is the feature the current code buys.

**Resize the raster to 192, one file for both roles.** Google states the favicon must be square with a side that is a multiple of 48px. 180 is not. 192 is 48x4 and within one step of 180, so the Apple touch icon loses nothing visible — iOS accepts any square size and scales. Alternatives: keep 180 and hope the rule is soft — the whole point of the change is to stop guessing at the crawler; add a second 192 raster and keep 180 for touch — two files, two regeneration steps, for pixels nobody can see.

**Root-relative `/favicon.png`, matching `apple-touch-icon` and `math.html`.** Consistent with existing hrefs. On a `file://` copy this path does not resolve, but the script overwrites the `href` at load before the browser settles on an icon, so a saved copy still shows the mark. A JS-disabled saved copy shows no icon — same as today, since today it has no `href` at all.

**`tools/mkicon.py` parameter change only.** `S = 180` becomes `S = 192`; output filename follows. Supersample factor, geometry, palette, quantization all unchanged — the script already scales everything through `k = n / 32.0`.

**Skip `/favicon.ico`.** Google's `.ico` fallback is for pages that declare no icon link. This one will declare a valid one. Add the redirect row only if the icon is still missing after reindexing.

## Risks / Trade-offs

- Google renders pages and may read the post-script `data:` URI instead of the static file → the favicon fetcher is documented as crawling the declared URL from the HTML; if the icon is still blank after a reindex cycle, the fallback is to stop overwriting the `href` on the hosted copy, or add `/favicon.ico` to `_redirects`.
- `icon-180.png` deleted while an external bookmark or cached page still points at it → `_redirects` rows cover the conventional `/apple-touch-icon*.png` paths; a direct `/icon-180.png` link breaks. No known external reference. Add a redirect row if one surfaces.
- `math.html` is generated by `tools/mkmath.js`; editing the built file alone gets overwritten on next build → change the icon href in whichever of the two the head markup comes from, then rebuild and confirm.
- Reindexing lag: nothing verifiable at merge time beyond the markup and the file → verification is limited to "static href present, file is 192 square, self-check passes, no 404s".

## Migration Plan

1. `tools/mkicon.py` to 192, run it, commit `favicon.png`, delete `icon-180.png`.
2. Retarget the three hrefs and two `_redirects` rows.
3. Deploy; confirm `/favicon.png`, `/apple-touch-icon.png`, `/apple-touch-icon-precomposed.png` all 200.
4. Request reindex in Search Console; favicon appears on Google's schedule, not on deploy.

Rollback: revert the commit; `icon-180.png` returns with it.
