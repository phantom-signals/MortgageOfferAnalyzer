# page-icon Specification

## Purpose
How the page declares its icon: a static raster named in the served markup so a crawler that never runs script still finds a fetchable icon URL, the runtime upgrade of that href to the theme-aware `#mark` SVG, the square multiple-of-48 size rule search engines apply, the reuse of the one raster as the Apple touch icon, and the rule that `#mark` stays the single definition of the artwork.
## Requirements

### Requirement: Icon is declared in static markup
The page SHALL declare its icon with a `<link rel="icon">` carrying a non-empty `href` in the served HTML, pointing at a same-origin raster file beside the page. The `href` SHALL NOT depend on script execution to exist. A crawler that reads the raw HTML and never runs the page's script SHALL find a fetchable icon URL.

#### Scenario: Raw markup carries the icon URL
- **WHEN** the served HTML is fetched and parsed without executing script
- **THEN** a `<link rel="icon">` element is present
- **AND** its `href` attribute is non-empty and resolves to a same-origin image file
- **AND** fetching that URL returns an image

#### Scenario: Crawler-visible after render
- **WHEN** a renderer executes the page's script and then reads the icon link
- **THEN** a fetchable icon is still declared, whether as the static file or as the runtime data URI

### Requirement: Icon raster meets search-engine size rules
The icon file SHALL be square with a side length that is a multiple of 48 pixels, so it is not rejected by search-engine favicon indexing. The file SHALL be generated by `tools/mkicon.py` from the `#mark` artwork, not drawn by hand.

#### Scenario: File dimensions
- **WHEN** the icon file's header is read
- **THEN** its width equals its height
- **AND** that side length is a multiple of 48

#### Scenario: Regeneration
- **WHEN** `tools/mkicon.py` is run
- **THEN** it writes the icon file at that size
- **AND** the written artwork matches the `#mark` geometry: house outline plus three ascending bars

### Requirement: Script upgrades the icon to the mark SVG
On load the page's script SHALL overwrite the `rel="icon"` `href` with a `data:image/svg+xml,` URI serialized from the `#mark` SVG element. The `#mark` SVG SHALL remain the single definition of the artwork; no second inline copy of the path data is added to the markup.

#### Scenario: Runtime overwrite
- **WHEN** the page loads with script enabled
- **THEN** the `rel="icon"` `href` is a `data:image/svg+xml,` URI whose decoded content is the `#mark` element's markup
- **AND** the tab icon follows the mark's light and dark rules

#### Scenario: Single artwork definition
- **WHEN** the markup is searched for the mark's path and bar coordinates
- **THEN** they appear once, in the `#mark` SVG

#### Scenario: Offline copy
- **WHEN** the page is saved to disk and opened from `file://` with no network
- **THEN** the script's overwrite supplies the icon
- **AND** the failed fetch of the static `href` produces no visible error and changes no computed figure

### Requirement: Touch icon reuses the same file
The `rel="apple-touch-icon"` link SHALL point at the same raster file as `rel="icon"`, on its own `<link>` element with a single-token `rel`. The `_redirects` rows for `/apple-touch-icon.png` and `/apple-touch-icon-precomposed.png` SHALL resolve to that same file. No second raster is kept in the repository.

#### Scenario: One raster serves both roles
- **WHEN** the head's icon links are read
- **THEN** `rel="icon"` and `rel="apple-touch-icon"` name the same file path
- **AND** exactly one icon raster exists in the repository

#### Scenario: Conventional touch-icon paths resolve
- **WHEN** `/apple-touch-icon.png` or `/apple-touch-icon-precomposed.png` is requested from the hosted page
- **THEN** the response serves that same raster
- **AND** no request 404s

#### Scenario: Sibling page icon
- **WHEN** `math.html` is loaded
- **THEN** its `rel="icon"` href resolves to the same existing raster
- **AND** it does not reference a deleted filename

### Requirement: Icon change alters no computed behavior
Changing the icon markup, filename, or generator SHALL NOT alter any input, computed figure, verdict, definition popover, or self-check outcome, and SHALL NOT require a Content Security Policy change.

#### Scenario: Self-check unaffected
- **WHEN** the page is opened with `#selftest`
- **THEN** it passes

#### Scenario: Policy unchanged
- **WHEN** the page loads from the host with its existing `Content-Security-Policy` meta
- **THEN** the static raster and the data URI icon both load
- **AND** no policy violation is reported in the console
